# Проверка PURSOV STUDIO 2.0

Дата: 6 ноября 2026 года. Статус: пилотный выпуск; основной канал автоматических обновлений включён.

На основном компьютере с Windows 11 прошли миграция 1.0.1 → 2.0.0, обновление MSI до 2.0.1 и обновление **2.0.1 → 2.0.2 через кнопку приложения** после автоматической загрузки. Новая версия перезапустилась без повышения прав, восстановила подключение и прошла технические пробы Telegram, Discord и YouTube. Реальные сообщения, голосовой звонок и длительное воспроизведение остаются отдельными проверками. Ошибки ранних попыток сохранены в отдельных отчётах.

## Выполнено

- Release-сборка без ошибок и предупреждений; автономный x64 MSI с .NET, Python и зафиксированными сетевыми компонентами.
- 14 групп самопроверок приложения: разбор стратегий, отмена, независимая остановка компонентов, состояние, настройки и изоляция журнала самопроверки.
- Изолированные проверки парсера/процессов (5 групп), службы Telegram (3), Python runner (6), брокера (7, включая исправление 2.0.1), доверия обновлениям (21), ACL помощника установки (6).
- 24 проверки таблиц MSI: определение версии Windows, службы, ярлыки, порядок обновления/отката, комплектность и отсутствие пользовательских секретов.
- Сверка подписей, размера, версии и SHA-256 настоящих MSI, включая пары 1.9.99 → 2.0.0 и 2.0.1 → 2.0.2, с отклонением понижения версии.
- [Итоговый прогон `v2.0.2` на Windows Server 2025](https://github.com/Pursov-Labs/pursov-studio-releases/actions/runs/42138294793): **45 проверок жизненного цикла и 10 проверок установленного помощника миграции прошли**. Выполнены чистая установка 2.0.1, запуск/остановка службы, намеренный сбой после инициализации новой версии, откат, настоящее обновление до 2.0.2 и удаление. Проверены побайтовое восстановление файлов приложения и общих сетевых данных, активная версия и сохранение прав службы; сохранены тестовые настройки, синтетический секрет Telegram и пользовательский сетевой список. Дополнительные проверки используют настоящий заблокированный файл и проверяют перенос старой установки, восстановление и новую попытку после завершённого отката. SHA-256 пакета 2.0.2 совпадает с опубликованным выпуском и локальным MSI: `bb4a7538a0fa83fc5dd5234545bfcc10573158be341d39d30c4227fdc876ff45`. [Машиночитаемый отчёт 2.0.2](qa/installer-windows-server-2025.json).
- [Прогон `v2.0.1-preview.1`](https://github.com/Pursov-Labs/pursov-studio-releases/actions/runs/42137699802) прошёл 45 проверок жизненного цикла и 10 проверок помощника для перехода 2.0.0 → 2.0.1. Проверенный MSI 2.0.1 совпадает с установленным на основном компьютере. [Отчёт сохранён отдельно](qa/installer-windows-server-2025-2.0.1.json).
- [Предыдущий прогон `v2.0.0-preview.3`](https://github.com/Pursov-Labs/pursov-studio-releases/actions/runs/42088967577) также прошёл 45 проверок жизненного цикла и 10 проверок помощника для перехода 1.9.99 → 2.0.0. [Отчёт сохранён отдельно](qa/installer-windows-server-2025-2.0.0.json).
- Живая установка обнаружила ошибку использования свойства MSI `WindowsBuild`: оно возвращало совместимое значение 9600 на современной Windows. Проверка заменена чтением `CurrentBuildNumber` из 64-разрядной ветки реестра. При миграции 1.0.1 обнаружена блокировка старого файла драйвера во время очистки. В `preview.3` завершённая операция допускает сохранение проверенных занятых файлов для последующей очистки; следующая попытка получает отдельный каталог снимка. Старое дерево программы переносится в защищённую резервную копию перед установкой нового.
- На Windows 11 Pro, сборка 26200, MSI `preview.3` завершился с кодом 0 и установил 2.0.0.0 поверх 1.0.1.0. Все **989 установленных файлов** совпадают с выпуском по SHA-256. Новая резервная копия содержит 1021 прежний файл; 40 файлов, присутствовавших только в старой установке, отсутствуют в новом каталоге. Настройки и Telegram-конфигурация сохранили прежние SHA-256 до первого запуска. Три пользовательских списка также не изменились. Проверены 3404 объекта защищённых каталогов, автозапуск `--signin` и запись установленного приложения. [Отчёт о миграции](qa/host-windows-11-preview3.json).
- В 2.0.0 подключение без повышения прав завершалось ошибкой «Отказано в доступе». При проверке дескрипторов службы были доступны `QUERY_STATUS` и `START`, а `QUERY_CONFIG` был запрещён. [Сохранённые результаты до исправления](qa/host-service-access-2.0.0.json).
- Обновление до 2.0.1 на Windows 11 завершилось с кодом 0; все 989 файлов совпали с выпуском, настройки и Telegram-конфигурация сохранились до подключения. Повышенный процесс записал полные дескрипторы службы до и после обновления: для интерактивных пользователей `LCRP` заменено на `CCLCRP`. Независимая проверка без повышения прав подтвердила доступ к `QUERY_CONFIG | QUERY_STATUS | START` (`0x15`) и запрет остановки, изменения конфигурации, удаления, смены владельца и DACL. Проверка только открывала и закрывала дескрипторы, не меняя состояние службы. [Отчёт 2.0.1](qa/host-windows-11-2.0.1.json).
- В обычном сеансе 2.0.1 кнопка подключения привела к состоянию «Подключено». Интерфейс показал «Прокси отвечает» для Telegram, «Соединение отвечает» для Discord и «Видеофрагмент получен» для YouTube; время проверки — 6 ноября, 03:31 по Москве. Собственный Python-процесс слушал `127.0.0.1:1443`. Эти результаты подтверждают технические пробы; сообщение Telegram, голосовой звонок Discord и длительный просмотр YouTube ещё не проверены.
- При обычном запуске из Explorer приложение автоматически загрузило 2.0.2. После нажатия «Установить» MSI завершился с кодом **0**, прежнее окно закрылось, помощник запустил новую версию с восстановлением подключения. В новом процессе `TokenElevation=0`; UI показывает 2.0.2, «Подключено» и успешные технические пробы всех трёх сервисов, время — 6 ноября, 04:09 по Москве. Все **989 файлов** совпали с выпуском; защищённый MSI, манифест и подпись совпали с опубликованными материалами. Отдельная попытка ручного переноса настроек не завершилась и ничего не заменила: обычный запуск использовал существующий пользовательский профиль. [Отчёт об обновлении через приложение](qa/host-in-app-update-2.0.1-to-2.0.2-native.json).
- 6 проверок представления состояния; проверки геометрии и 13 визуальных снимков WPF. Настоящее окно при 100% DPI, клавиатурный фокус, переход к сведениям о программе и возврат проверены через Windows UI Automation.
- Светлая/тёмная темы просмотрены; контрастные цвета проверены в ресурсах. Физическое переключение высокой контрастности и Narrator ещё не проверены.
- Исходники оболочки сверены с архивом; пять архивов исходников upstream проверены по зафиксированным SHA-256. Закрытый ключ и пользовательские данные исключены из публикации.
- Ручное ревью границы прав и обновлений: исправлены откат данных ProgramData, повторное использование неудачной транзакции, небезопасные существующие каталоги, запуск во время установки и порядок запуска помощника перезапуска.

Числа обозначают группы проверок; отдельные проверки могут пересекаться между наборами. Они не доказывают отсутствие всех ошибок.

## Нагрузка

Установленная **2.0.1.0**, подключение включено: два последовательных замера на одной системе с 16 логическими процессорами. В каждом — 120 отсчётов с интервалом 5 секунд.

| Режим и отчёт | Длительность | Средний суммарный CPU | Пик суммарной приватной памяти |
| --- | --- | --- | --- |
| [Открытое окно](qa/performance-installed-2.0.1-window.json) | 600,064 с | **0,388%** | **199,93 МБ (190,66 МиБ)** |
| [Трей](qa/performance-installed-2.0.1-tray.json) | 600,057 с | **0,016%** | **193,96 МБ (184,97 МиБ)** |

Пределы 0,5% CPU и 250 МБ выполнены в обоих режимах для четырёх собственных процессов: интерфейса, брокера, Telegram-прокси и сетевого компонента. Все четыре процесса присутствовали во всех отсчётах без смены идентификаторов; разрывов измерения свыше двух интервалов нет. Перед вторым замером окно закрыто в трей, отсутствие видимого окна и продолжение работы процесса проверены через Windows UI Automation.

CPU нормирован на все логические процессоры. Память ядра и драйвера не измеряется; краткие процессы и пики между отсчётами могут быть пропущены. Измеряющий PowerShell/CIM не включён в нагрузку приложения. Замеры относятся к подключённому состоянию без ручной диагностики и целевого пользовательского трафика. В 2.0.2 изменены изоляция журнала самопроверки и её проверка, однако результаты выше не выдаются за измерение 2.0.2.

Исторические замеры только интерфейса в режиме предварительного просмотра: два раза по 10 минут, средний CPU 0,00114% / 0,00357%, максимальная приватная память 81,31 / 94,26 МиБ. В этом режиме `--signin` не скрывал окно, поэтому исходная отметка первого измерения «tray» исправлена. Сетевые процессы, служба, трей и трафик в эти старые замеры не входили; для оценки полного приложения используются результаты установленной версии выше.

## Не завершено

- Чистая установка, перезагрузка/автозапуск, обновление, принудительный откат и удаление на Windows 10 22H2. Для Windows 11 подтверждены миграция существующей 1.0.1 → 2.0.0, обновление MSI до 2.0.1, обновление через приложение до 2.0.2 и техническое подключение без повышения прав; остальные сценарии остаются отдельными проверками.
- Проверка обычного пользователя с паролем другого администратора, двух сеансов, сна, смены сети и реальных конфликтов с другими установленными сетевыми средствами.
- Передача реального Telegram-сообщения, голосовой звонок Discord и длительное воспроизведение YouTube. UI различает запуск процессов, технические пробы и непроверенные пользовательские функции.
- Физические масштабы 125–200%, перенос между мониторами, экран 1366×768 и Narrator.

Пользователь подтвердил UAC и разрешил установку на основном компьютере; миграция до 2.0.0 и последующие обновления до 2.0.1 и 2.0.2 выполнены. Hyper-V доступен, подготовленных тестовых ВМ пока нет. Защита Windows не отключалась. Defender ранее заблокировал отдельно скачанный официальный архив WinDivert при дополнительном сравнении; поведение конечного MSI на других чистых системах требует проверки.

Остаётся ограничение восстановления после частичного сбоя самого отката: если перенос общих данных уже выполнен, а восстановление старого дерева затем прервётся, повторный откат требует проверки сохранённых копий. Обычный принудительный откат и сохранность копий проверены; повтор после такого промежуточного сбоя пока не автоматизирован.

Запуск плагина Codex Security завершился ошибкой «The selected scan target changed while the scan was starting». Канонического отчёта сканера нет; ручное ревью выше не выдаётся за результат Codex Security.

## Канал выпусков

Версия [2.0.2](https://github.com/Pursov-Labs/pursov-studio-releases/releases/tag/v2.0.2) была временно опубликована в основном канале для проверки обновления. Публичные `release.json` и `release.sig` совпали с подписанными материалами сборки. После нажатия «Установить» служба сообщила, что не найден `release.json` в пользовательском каталоге подготовленного пакета. Транзакция завершилась состоянием `failed`, кодом `-1`, до запуска MSI. Прежняя версия 2.0.1 сохранилась и автоматически восстановила подключение; это не результат отката Windows Installer, поскольку установка не началась. [Сводка наблюдений и результата](qa/host-in-app-update-2.0.1-to-2.0.2.json).

Причина первой попытки подтверждена: приложение, запущенное из Codex, унаследовало перенаправление файловой системы MSIX. Загруженные файлы физически находились в `LocalCache/Local` пакета Codex, тогда как служба обращалась к настоящему пользовательскому `LocalAppData`. Это сбой окружения тестового запуска; для его устранения производственный код не менялся. После установления причины основной канал 2.0.2 включён снова. Повтор через обычный запуск Explorer прошёл: автоматическая загрузка, нажатие кнопки, установка с кодом 0, перезапуск обычного пользовательского процесса и восстановление подключения подтверждены в [отдельном отчёте](qa/host-in-app-update-2.0.1-to-2.0.2-native.json). Предыдущие предварительные выпуски доступны для ручного скачивания; приложение не предлагает их как автоматические обновления.

Подпись манифеста проверяется встроенным публичным ключом. Она не заменяет Authenticode/репутацию SmartScreen для первоначального установщика.
